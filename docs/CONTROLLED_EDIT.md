# Controlled workload edits

KBorg supports reviewed image and optional CPU/memory request/limit changes to one existing ordinary container in a Deployment, StatefulSet, DaemonSet or CronJob. The TUI `e` form starts from fresh current values and can prepare one combined change. Leaving resource editing disabled preserves the complete original resource configuration. General manifest patches, privilege changes, init-container edits, Secret edits and RBAC edits are outside this operation.

Use `kborg --context CONTEXT -n NAMESPACE --write set-image [RESOURCE] NAME CONTAINER IMAGE`. Omitting RESOURCE retains the deployment shorthand. `set-resources [RESOURCE] NAME CONTAINER CPU_REQUEST MEMORY_REQUEST CPU_LIMIT MEMORY_LIMIT` changes the four reviewed budget fields. Review the complete before/after diff, endpoint, context, namespace, name, UID and resourceVersion before typing the displayed namespace/name confirmation. Approval is single use, expires after 60 seconds and is bound to the exact change and target.

Images accept a conservative bounded ASCII registry/repository reference with tag or a complete SHA-256 digest. Tags can change remotely; KBorg does not attest image provenance. The selected container must exist exactly once. Known Argo CD and Flux labels/annotations block direct edits and provide source-repository guidance. Unrecognized custom GitOps conventions require organization policy.

The strategic merge patch contains UID/resourceVersion, the selected container name, and only the reviewed image/resource fields. CronJobs use their nested Job template. Environment values, unrelated containers and unreviewed resource fields are preserved. The server performs dry-run admission first; the complete resulting spec must match the requested change. Equivalent Kubernetes quantity spellings are normalized only for the reviewed budget fields. Additional spec mutations block approval. The actual write repeats UID/resourceVersion preconditions without automatic retry; admission can still change between dry-run and execution.

Dry-run metadata protection compares labels, annotations, ownerReferences, finalizers, name, namespace and UID. Technical resourceVersion/managedFields differences are permitted. Kubernetes apps/v1 DaemonSets also increment `deprecated.daemonset.template.generation` when their Pod template changes: only the exact canonical positive-counter increment is permitted, with every other annotation unchanged. This exception was confirmed on Docker Desktop Kubernetes 1.36.1 and does not relax full-spec comparison.

Scale supports Deployments and StatefulSets, with 0..20 replicas. Restart supports Deployments, StatefulSets and DaemonSets. OnDelete strategies explicitly require Pod replacement before new templates take effect; CronJob edits affect future Jobs. These workflow differences appear in review.

Audit records retain operation name, target identity and outcome without image, container, resource values, patch or workload content. Action debug formatting also omits values. Durable intent/outcome storage and unknown-outcome handling apply; local filesystem/ACL and protected external audit gates remain.

Unit and mock tests cover GitOps, exact approval binding, read-only rejection, sensitive canary exclusion, narrow patch paths, preserved fields, quantity equivalence and unexpected admission mutations. Current real-cluster evidence for the expanded families is in [K9S_ACCEPTANCE.md](K9S_ACCEPTANCE.md); earlier reports apply only to their recorded source.
