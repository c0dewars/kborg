# Mac v1 security review

Reviewed 2026-10-23 on macOS ARM64, starting from commit `6339cc9`. This is an internal adversarial code and regression review, supported by a refreshed dependency advisory scan. It is not an independent external assessment or security certification.

## Fixed findings

**MAC-REVIEW-001 — Medium: ambiguous Unicode in approval screens.** The TUI deliberately renders untrusted data in ASCII-only cells. Its final cell renderer previously replaced each non-ASCII character with `?`, while approval coverage wrapped and counted the original string. As a result, different Unicode context names, Helm manifest strings or direct command arguments could look identical in a review that could still be approved. This did not execute terminal escape sequences or bypass the exact operation/UID checks, but weakened the user's ability to distinguish what they were approving.

Approval content now receives a reversible ASCII presentation before wrapping and painted-line accounting. For example, `é` appears as `\u{e9}` and a literal backslash is doubled. A short legend appears only when escaping is necessary. ASCII text without backslashes retains its existing presentation. The sealed request, confirmation target and transmitted bytes are unchanged. Expanded presentation exceeding 1 MiB blocks approval with a visible explanation; nothing is silently truncated.

The fix applies to YAML and node maintenance reviews, Helm reviews, legacy mutations and shell/forward confirmations, local export destination reviews, and Copilot diagnostic-transfer reviews. Ordinary resource-list presentation continues to use its conservative ASCII display policy.

Regression coverage checks distinct Unicode values, literal escape-spelling collisions, terminal controls, complete escaped-line coverage at narrow widths, width changes, and expansion refusal. The mutation/session test also passes the escaped presentation through the real data-cell formatter.

**MAC-PACKAGE-001 — Medium: unchecked source labels and overstated package evidence.** The packaging script accepted any 40-character source commit, packaged a previously built executable without binding it to the checkout, accepted any successful version output and unconditionally claimed native CI unit tests. This could produce internally consistent unsigned records that misidentified the packaged source or testing. The checksum verifier already correctly disclaimed publisher authentication and was not itself a source-authentication check.

The packager now requires the supplied commit to equal a clean HEAD; packaged inputs must be tracked regular files, including files ignored by Git status. It verifies native compiler/process architecture, builds into a new isolated target directory, checks the exact package version, binds the copied executable to the hash that passed smoke checks, and repeats clean-source checks before creating the archive. Compiler override environment variables are rejected. Native archive inspection also exposed macOS AppleDouble metadata records; the Mac tar invocation now omits extended attributes, ACLs, file flags and AppleDouble sidecars. BUILD schema 2 records actual build/packaging times and the smoke checks performed; it explicitly says unit tests are not run by the packager. Nine isolated negative fixture checks cover source mismatches, dirty/untracked/ignored/linked inputs, wrong native host, a stale-binary/version mismatch, and supplied-digest matching/refusal. These fixture checks are not the separate real native-package acceptance run.

The build record remains unsigned. Clean-tree checks do not establish a trustworthy compiler, protect against a hostile same-user process, prove bit-for-bit archive reproducibility or authenticate the publisher. The fresh build may produce a different executable hash from another build of the same source; exact binary acceptance must retain its own hash.

**MAC-REVIEW-002 — Low: export approval while its review was hidden.** A terminal narrower than 28 columns suppresses all modals, but export approval checked only whether the wrapped review could fit vertically. An actual pre-fix PTY run at 20×100 created a private snapshot without painting the export review. The scope is unintended local persistence: private-file permissions, create-only behavior, destination constraints and export size limits still applied; no remote mutation or arbitrary destination bypass was demonstrated.

Export approval now requires the renderer’s minimum 28×10 dimensions and complete wrapped content fit. Export, YAML/node, Helm and Copilot approval handlers also reject terminal-size lookup failures instead of assuming 80×24; legacy mutation/session handlers already rejected those errors. The production handler reads the real terminal size. A private injectable test seam verifies the actual handler, with a test-only owned temporary export fixture.

[Regression evidence](evidence/mac-v1-export-approval-regression.json) records the expected failure on the old executable and **64 passing layout tests**, including hidden 20×100, 27×100 and 120×9 reviews creating no file, an unknown-size export creating no destination, an explicit valid 120×34 save, and unknown-size refusal of a fully reviewed Helm dispatch. The correction is committed in `2a33306`; the corrected native executable passes seven [actual export PTY checks](evidence/ui-mac-v1-hardening-final/exports/report.json). The fresh package executable independently passes the same [seven export checks](evidence/ui-mac-v1-package/exports/report.json). A read-only cross-review found the other minimum-size gates already aligned with the renderer; paged approval accounting matches the actual content area and follows successful output flushing.

## Remaining release gates and limits

Independent external security assessment, a realistic organizational pilot, publisher signing/notarization, and release deployment controls remain open. Least-privilege Kubernetes RBAC, admission policy and protected external audit are operator responsibilities. The dependency scan is a point-in-time known-advisory check; it does not cover undisclosed flaws or every native tool and OS component.

Same-user filesystem and executable replacement races are reduced by validation, snapshots and hashing, but these are not a universal OS sandbox. Native Helm and Kubernetes subresources retain their documented concurrent name-recreation races. Redaction does not identify arbitrary confidential custom fields. Terminal and soak results should be read from this batch's acceptance reports; neither a bounded local soak nor this internal review proves production resilience or broad terminal compatibility.
