# KBorg 0.8.0 — 2026-11-16

- **Undo the last change.** After a scale, an image change, or a suspend or resume succeeds, `z` (or `:revert`) prepares the reverse: the old replica count, the old image, or the opposite suspend. It goes through the same review, dry run and approval as any change. The old value is read just before the change is approved. The reverse is bound to that object's UID, so it is refused if the object was replaced. Restarts, deletes, kills and triggers cannot be undone and offer no undo; a failed change leaves nothing to undo, and any later change replaces it. (`:undo` stays the k9s-style alias of `:rollback`.)
- **A short first-run tour.** After you pick a theme on the very first start, three tips show how to get around: `:` and a resource name, `?` for the keys of any view (and that every change shows a review first), and Ctrl-P for the palette. Each tip names your own keys. Enter shows the next, Esc skips the rest, and `:tour` shows it again any time.
- **A PODS column on Nodes.** The Nodes table shows how many Pods run on each Node, counted as `kubectl describe node` does (Pods that have not finished), like k9s's `PODS`. It is counted in the background at most every 30 seconds while the table shows it, reading only each Pod's Node name; on a very large cluster the count stops at 50,000 Pods and reads `N+`. Use `PODS` in `views.yaml` like any predefined column.
- **Describe (`d`) shows why something failed.** Under the overview, the view now lists each container's last termination (reason, exit code and time, such as `OOMKilled (exit 137)`) and the object's recent events, newest first, as k9s's describe does. The events are those of that exact object, matched by kind, name and UID, so the events of a deleted object of the same name never show. A refused event read says so instead of looking like no events. `kborg describe` reads its events the same way now, with a server-side field selector instead of listing the whole namespace.
- **Long names keep their ending.** A NAME too wide for its column now loses its middle instead of its end (`payments-~b6-x2kqp`), so Pods of one ReplicaSet stay apart. The header bar shows where you are: on a screen about one object, the kind, the object and the screen (`Pods › api-7d4f9c8b6-x2kqp › details`), with a long name cut the same way.
- **Bring your k9s skin.** `kborg theme import-k9s ~/.config/k9s/skins/NAME.yaml` saves a k9s skin as a new theme (`k9s-NAME`, or `--id ID`) and prints where each color came from. Colors the skin leaves to the terminal come from KBorg Dark, and a color too faint to read keeps its hue but is made readable (4.5:1), so every imported theme passes the same contrast checks as the built-in ones. It never replaces a theme.
- **Dashboard charts remember the last 7 days.** In the chart panel (`G`), `H` switches between the last 15 minutes, 24 hours and 7 days, so yesterday's restarts are still there after you close KBorg. Each cluster keeps a 5-minute series of counts and percentages only (Pods needing attention, restarts, Node CPU and memory) in a private `history/` folder of the KBorg config folder, at most 256 KiB per cluster and written at most once a minute. Nothing is saved for demo data, and `dashboard.history: false` in `ui.yaml` turns it off.
- **Faster starts on custom resources.** KBorg keeps the API discovery catalog on disk for 10 minutes per API server and kubeconfig identity (private, in `cache/discovery/` of the config folder, named by a hash), so `kborg ui CRD`, a saved selection or `kborg get CRD` no longer waits for discovery. It rediscovers after every connect and replaces the cache; a cached catalog is checked like a discovered one and never holds Secrets. Discovery now also handles larger clusters: up to 2,000 resource kinds in 300 API groups (was 200 and 100, beyond which discovery failed).
- **Accessibility mode and color-blind-safe themes.** `accessible: true` in `ui.yaml`, or `KBORG_ACCESSIBLE=1`, turns off the startup animation, box drawing, the logo, zebra rows, braille charts and card sparklines, and places the terminal cursor on the selected row after every frame, so screen readers that follow the cursor read the row you are on. Two new themes use the Okabe-Ito colors, which stay distinct with the common color-vision deficiencies: `okabe-ito-dark` and `okabe-ito-light`. `k8borg-high-contrast` is now tested to meet 7:1 (WCAG AAA) for all text.
- **Scroll a table sideways.** When a table's columns do not all fit, Left and Right move them, as in k9s. With the mouse, Ctrl or Shift with the wheel scrolls sideways, and so does a sideways wheel or trackpad swipe; in the log view they scroll long lines. NAMESPACE and NAME stay in place, and NAME keeps room for the names shown (up to a third of the width) instead of being squeezed. The table title says how many columns are hidden on each side (`<2 | 3 more>`). This works in every table, Pods included (NODE and IP are to the right on a narrow terminal), and Ctrl-W adds LABELS to the tables without their own columns. Before, the columns that did not fit were dropped, so wide-mode, `views.yaml` and CRD columns could not be seen on a narrow terminal at all. Another resource starts at its first column. Both keys can be remapped (`columns.left`, `columns.right`). Some terminals keep Ctrl or Shift with the wheel for themselves (zoom, or selecting text); Left/Right always work.
- **Edit a whole Secret.** In `:secrets`, `E` opens every key and value of the Secret in front in KBorg's editor, as text: multi-line values such as certificates as YAML blocks, others as quoted strings. Change values, add keys or delete a key's line, then Ctrl-S. The review lists each key set, added or removed with its size, never a value, and the change is one patch locked to the Secret's UID and the version you opened, so if someone changed the Secret meanwhile it is refused instead of overwritten. Values that are not text (binary) are listed under `keep:` and stay as they are. Unlike k9s, the values are decoded (no base64), never written to a file (`$EDITOR` is not offered for Secrets), never sent with `:ask`, and the editor's buffer is overwritten when it closes (best effort: copies the system made while you typed are not). Esc from the review returns to your draft. Each document is checked to read back byte for byte before it is shown. Read-only sessions and `allow_secret_edit: false` cannot open it.
- **Custom resources show their own columns.** A custom resource's table now shows the columns its CRD defines (`additionalPrinterColumns`), as k9s and `kubectl get` do, instead of Pod columns that were mostly empty. `:nodeclaims` shows TYPE, CAPACITY, ZONE, NODE, READY and AGE; Argo CD Applications show SYNC-STATUS and HEALTH-STATUS; Flux, cert-manager and other operators' resources show their READY and STATUS columns. Each of these columns is as wide as its values, as in k9s. Columns the CRD marks as extra (`kubectl get -o wide`) appear with Ctrl-W. KBorg reads each CRD once per connection, when you first open that resource. Without permission to read CRDs, the table keeps the generic columns. `views.yaml` still wins. Column paths in `views.yaml` now also take JSONPath filters such as `READY:.status.conditions[?(@.type=="Ready")].status`.
- **Browse more than 10,000 objects.** A scope too large to watch live (over 10,000 objects or 64 MiB) used to show only its first 10,000 objects. Now `>` reads the next 10,000 and `<` goes back, using the API server's continue tokens, and the status line says where you are: `Page 2: objects 10001–20000 of 52340`. Pages end on the server's page boundaries, so no object is skipped or shown twice. Each page still refreshes every 30 seconds; sort and `/` filters apply to the page shown, while `/-l LABELS`, a field selector or `:ns` narrow the scope on the server and go back to page 1. If the server's token for a page has expired, KBorg says so and `<` returns to the first page. Both keys can be remapped (`list.next`, `list.prev`).
- **Fixed: Copilot setup refused Copilot CLI updates.** Setup ended with "Setup did not finish" once the Copilot CLI updated itself past 1.0.91, because KBorg accepted only that exact version. KBorg now accepts 1.0.91 or later when the installation passes the same containment checks. Copilot CLI 1.0.112 removed `--no-remote`; KBorg now picks the switch the installed version offers to keep the session local (`--sync-session=off` from 1.0.112) and refuses to send when there is none. The sandbox now allows Copilot's package cache for any version, not only 1.0.91. 1.0.112 also checks TLS certificates through macOS's Security framework, so the sandbox allows one system service, `com.apple.SecurityServer`; keychain files and the data-protection keychain stay out of reach (a keychain dump under the same rules finds no items). Checked live: setup, a question and a follow-up on 1.0.112. Rerun `kborg copilot setup` after upgrading.

# KBorg 0.7.0 — 2026-11-15

KBorg now works with AI assistants. A built-in skill teaches GitHub Copilot, Claude, Codex, Gemini and other assistants to inspect and debug clusters with KBorg's read-only commands, to ask before any change, and to help with keys, themes and config. This release also closes the privacy gaps an audit of that path found.

- **A skill for AI assistants.** KBorg ships an Agent Skills folder (`SKILL.md` and eight references). With it Claude Code, GitHub Copilot, OpenAI Codex, Gemini CLI and other assistants can help with all of KBorg:
  - finding and remapping keys, hotkeys and aliases
  - creating and changing themes, `ui.yaml` and table columns
  - per-cluster settings such as PROD badges and read-only clusters, and team restrictions
  - dashboards and saved selections, moving over from k9s, plugins, editors, scanners and Copilot setup
  - explaining screens and reviews, installing, and troubleshooting

  The skill tells the assistant to take facts from the installed KBorg, running the commands itself or, in a chat, asking you to run them. It must check every file it writes, leave approvals to you, and never ask for a credential or a Secret value. `kborg skill install` writes it into every assistant found on the machine and into `~/.agents/skills`; `kborg skill install NAME|DIR` targets one. `kborg skill print` prints it as one Markdown file for ChatGPT, Gemini and other chat apps. It is built into the binary, so it matches your version; rerun the install after upgrading. Install updates an earlier KBorg skill, removes references it no longer ships, and never writes into a folder that holds anything else. Every example in it is parsed by KBorg's tests.
- **Assistants can debug clusters with KBorg.** The skill's investigation guide tells an assistant how to inspect a cluster for you:
  - **How it runs commands:** always with `--read-only` and an explicit `--context`, never the TUI and never an endless stream.
  - **What to look at:** playbooks for crash loops, OOM kills, Pending Pods, image pulls, stuck rollouts, Services without endpoints, Node pressure, PVCs, Jobs and Helm releases.
  - **How it reports:** the cause with its evidence, and the fix as a command you run yourself. Cluster text is treated as data, not instructions.

  Without a terminal KBorg refuses every change, so an assistant's commands cannot write.
- **Assistants ask before any change, and KBorg enforces it.**
  - **In the skill:** before any change to a live cluster, an assistant must say what it changes and where, the risk and how to undo it. It then asks for a yes for that one change, and gives you the command to run yourself; KBorg's review is the second confirmation.
  - **In KBorg:** a write started without a terminal is refused, and so is one with `--read-only`, which the skill puts on every command.
  - **`KBORG_READ_ONLY=1`:** new. In the environment, it forces read-only for every command and the TUI, and no flag turns changes back on. Start your assistant with it (`KBORG_READ_ONLY=1 code .`, `KBORG_READ_ONLY=1 claude`); `kborg doctor` shows it.

  See [AI assistants: security and privacy](AI_ASSISTANTS_SECURITY.md).
- **Fixed: credentials in container arguments were shown.** `--password=VALUE`, `--token VALUE` and `NAME_PASSWORD=VALUE` in a container's `command` or `args` are now `[REDACTED]` on screen and in `kborg get`, `list --json`, `describe`, `watch`, exports and Copilot. In the YAML editor such an argument is read-only and preserved.
- **Fixed: more credential-named values are hidden on screen.** Describe, YAML, the YAML editor and `kborg yaml-template` now hide any text value whose name looks like a credential (`db_password`, `api-token`, `owner-token`, `aws_access_key`), as these notes already promised for 0.6.0. ConfigMap data with other names stays visible on screen.
- **`kborg yaml-template` is refused under `--read-only`.** It is the first step of an edit and prints ConfigMap data; use `kborg describe` or `kborg get` to read.
- **`kborg lint` names the missing request** (`no CPU request`, `no memory request`) instead of always saying "no CPU or memory request". **`describe` shows a Service's selector.**
- **`kborg describe RESOURCE NAME`** prints the describe view of one object for scripts and assistants: overview, containers, conditions, each container's last termination (reason and exit code, such as `OOMKilled`) and the object's recent events, newest first. `--json` returns the object and its events. It uses the same masking as `kborg get`.
- **`kborg keymap`** lists every action with its view, its keys now (your `keymap.yaml` applied), its default keys and what it does; `--json` for tools. `kborg keys` is the same.
- **`kborg config check`** validates every file in the config folder with the loaders KBorg itself uses: `ui.yaml`, `aliases.yaml`, `views.yaml`, `hotkeys.yaml`, `keymap.yaml` (including a hotkey that takes an action's key), custom themes, `contexts/*.yaml` (including the trust checks) and the extension registry. Each invalid file is named with its error and line, and the exit code is non-zero; `--json` for tools.

# KBorg 0.6.0 — 2026-11-15

- **ConfigMaps can be read and edited.** Describe (`d`), YAML (`y`) and JSON (`J`) now show ConfigMap `data` and `binaryData`, annotations and literal container `env` values, which used to appear as `[REDACTED]`. Describe lists each key with its value, or the first lines of a file. In the YAML view a multi-line value (an `nginx.conf`, an `application.properties`) is a readable block instead of one escaped line. The YAML editor (`e`) accepts changes to all of these, and its review lists the changed lines of a file, not the whole file.
- **What stays hidden.** Fields named like a credential (`password`, `token`, anything with `secret` or `credential` in its name) and the value of an `env` entry whose name is one (`DB_PASSWORD`, `API_TOKEN`, `AWS_SECRET_ACCESS_KEY`) are still `[REDACTED]` on screen and read-only in the editor. The same holds inside an annotation that carries a whole manifest, such as kubectl's `last-applied-configuration`: its copy is shown with those values masked, and it is read-only. Secrets are unchanged: `:secrets` with a timed reveal of one value.
- **Nothing more leaves the screen.** Copilot (`:ask`, Ctrl-G, `:copilot`), exports (`:export`), snapshots, external tools and the `kborg get` / `kborg view` commands get the same masked object as before. When you ask Copilot about a describe, YAML or JSON view, the capture is taken from the masked version of that view.
- **Secrets can be created and changed.** In `:secrets`, `n` creates a new Opaque Secret (its name, a first key and the value), `e` on a key sets a new value, `a` adds a key and Ctrl-D removes the selected key or, from the list, deletes the Secret. The value is typed into a prompt that shows stars (Tab shows it), or read from a file with `@/path/to/file` for certificates and other multi-line values; the bytes of a file are stored exactly. Every change goes through a review that names the key, its size before and after and where the value came from, lists the Pods that mount or read the Secret, and warns about a trailing line break, an empty value, TLS, registry, ServiceAccount-token and Helm-release Secrets, and Secrets a controller owns. A value never appears in the review, the audit record or an error. The change is checked with a server dry run and is cancelled if the Secret changed after the review. A new Secret is refused if the name is taken, and its review lists the Pods that already name it. An immutable Secret can only be deleted. `allow_secret_edit: false` in an operator config turns all of it off; the `kborg` command line has no Secret-changing command.
- **Port-forward to a Service or a workload.** `F` on a Service, Deployment, StatefulSet, DaemonSet or ReplicaSet finds a ready Pod behind it and opens the forward form on that Pod, with the Service's target port filled in (a named port is resolved on the Pod). The status line says which Pod was chosen. As with `kubectl port-forward svc/NAME`, the forward ends if that Pod goes away. The form now suggests one hour from every table, as it already did from the container list.
- **Scale ReplicaSets.** `s` and `kborg scale replicasets NAME N` work on a ReplicaSet. When a Deployment owns it, the review says that the Deployment sets the replica count back.
- **Jump to the owner.** `U` goes from a Pod to its ReplicaSet, from a ReplicaSet to its Deployment, from a Job to its CronJob, or to any other owner the cluster lists, with the table filtered to that one object. Esc goes back.
- **Used by.** `u` on a ConfigMap, PersistentVolumeClaim or ServiceAccount, and on a Secret in `:secrets`, lists the Pods of the namespace that mount it, read it into their environment, pull images with it or run as it, with each Pod's owner. Esc goes back to where you were.
- **Apply reviews show ConfigMap values.** The field-level diff of `:apply` prints ConfigMap data, annotations and plain env values as describe and YAML do, instead of "(value hidden)". Credential-named fields and every value of a Secret stay hidden, and a hidden value that changed is still listed as a changed line.
- **Reviews say which key approves.** The last line of a review said "Type NAMESPACE/NAME to apply" although `y` or Enter approves it; it now says "Press y or Enter". With `strict_confirmations: true` it still asks for the typed phrase.
- **Fixed: `o` on a Pod opened an empty Nodes table.** The jump to the Pod's Node used a filter that could not match a row. It now lands on the Node.
- **Your `keymap.yaml` wins over new default keys.** A key you bound stays yours: a built-in action of the same view that uses it gives it up, keeps its other keys or becomes unbound, and KBorg tells you on the status line and in `:keymap`. Before, such a clash stopped the whole keymap from loading, so every release that added a default key could break an existing file. A binding in one view still cannot take a key that works everywhere (`?`, `:`, Ctrl-P).
- **New default keys** `U` and, outside Nodes, `u`; in `:secrets`, `n`, `e`, `a`, `u` and Ctrl-D.

# KBorg 0.5.1 — 2026-11-14

- **One header on every view.** The k9s-style header now stays when you open describe, YAML, logs, a review, Secrets, Helm or help, instead of collapsing to the three-row bar. Its key hints are those of the view in front (search and close on a YAML view, filters and time ranges on logs), and its middle column names the view and, for logs and object overviews, what it shows. The namespace number keys are listed only on the table, where they work. The dashboard keeps its own layout, and full-screen logs (`f`) take the header's rows for log lines. Views have six fewer content rows than in 0.5.0; terminals under 100x24 and `header.style: bar` are unchanged.

- **Operate the whole cluster, not only application namespaces.** Changes now reach `kube-system`, `kube-public` and `kube-node-lease` (delete, edit, apply, shell, port-forward, Helm) and cluster-scoped objects (Nodes, Namespaces, ClusterRoles, CRDs, PersistentVolumes). Every change still goes through its review; a cluster-scoped object is confirmed by its name. The operator config can switch either off: `allow_system_namespaces: false`, `allow_cluster_scoped: false`.
- **Delete any kind.** `Ctrl-D` (and marked-row batches) works on every resource, not only the seven workload kinds: ConfigMaps, Ingresses, PVCs, ServiceAccounts, Roles, custom resources. The review warns when a delete reaches further than the row: a Namespace (everything in it), a Node, a CRD (every custom resource of that kind), a volume.
- **The YAML editor edits more than `spec`.** Every top-level field except identity and status (RBAC `rules` and `subjects`, StorageClass `parameters`, ...), plus labels and annotations, on namespaced and cluster-scoped objects. Values KBorg hides (ConfigMap `data`, existing annotations, `env` values) stay read-only and are preserved.
- **Apply handles real manifests.** Up to 64 objects per file (was 16), including cluster-scoped ones such as Namespaces, ClusterRoles and CRDs.
- **Drain works on real nodes.** It used to refuse a node when any Pod had an `emptyDir` volume, a critical priority, no controller or a custom controller, and it left `kube-system` Pods in place. It now evicts them as `kubectl drain --delete-emptydir-data --force` does and marks each such Pod with `!` in the review (data lost, not recreated, custom controller, critical priority). Up to 256 evictions (was 64) and a deadline of up to one hour (was 5 minutes; default now 10 minutes).
- **Longer sessions.** A port-forward can run for up to 12 hours (was 5 minutes; the form suggests one hour) and an interactive shell for up to 12 hours (was one hour). Scale accepts 0 to 10,000 replicas (was 20).

- **Pick the sort column from the keyboard or with a click.** `Shift-Right` and `Shift-Left` move the sort to the next column, `Shift-Down` and `Shift-Up` set descending and ascending, and a click on a column title sorts by it (again reverses). The k9s letters are complete: `T` restarts, `P` namespace, `O` node and `I` IP join `N`, `A`, `S`, `R`, `C` and `M`.
- **The mouse works everywhere, not only on table rows.** Every key hint in the header is a button, so are the `key action` items in a view's footer (close, search, confirm, cancel), a double click opens a row, and the wheel scrolls describe, YAML, logs and reviews. Where you are typing, a click never types a letter.
- **Copy mode.** `Ctrl-Y` (or `:mouse`) hands the mouse back to the terminal so you can select and copy text; the title bar shows `COPY MODE` until you press it again.
- **Destructive actions stand out.** Delete, kill and drain are drawn in the theme's danger color in the header and the key bar.

- **Filtering a large table is twice as fast.** With 20,000 Pods, typing a filter takes 0.19 s instead of 0.40 s, and sorting and clearing the filter are faster too: the sorted order and the text a filter matches are kept between keystrokes instead of being rebuilt for each one.
- **Messages no longer point at flags that are gone.** Everything is on by default, so a refusal now says what switched the feature off (`--read-only` or the operator config) instead of asking for `--write` or an `--allow-*` flag.
- **Editing a Role, binding or ServiceAccount warns about access.** The YAML edit review now carries the same "changes who may act" line as apply.

- **A smaller binary.** 13 MB instead of 18 MB on macOS, with the same speed: the release is now built with whole-program optimization.

# KBorg 0.5.0 — 2026-11-13

The first stable release since 0.4.0. It collects everything from the five release candidates below.

## New since 0.5.0-rc.5

- **k9s-style header.** The resource table opens with one item per line (Context, Cluster, User, Namespace, Kubernetes version with cluster CPU and MEM %), your recent namespaces with their number keys, the key hints in columns and, where the terminal has room to spare, a KBORG logo. The table title is centered in its border as `pods(all)[76/155]`, and only the status line stays below the table. Detail views, reviews and the dashboard keep the compact three-row bar, so their content keeps its height. Terminals smaller than 100x24 and `header.style: bar` in `ui.yaml` get the previous layout; `header.usage`, `header.namespaces` and `header.logo` turn the extras off. The table has four fewer rows than before at the same height.
- **Errors are red in every theme.** A failing row (CrashLoopBackOff, Error, Failed, ImagePullBackOff, ErrImagePull, CreateContainerConfigError, OOMKilled, Evicted, NotReady) is red across the whole row and a row still starting or stopping (Pending, ContainerCreating, Terminating, rolling out) is yellow; on the cursor row the color becomes the background. The host-palette `terminal` theme uses plain ANSI red and yellow. `ErrImagePull`, `InvalidImageName`, `OOMKilled` and `Evicted` now also count under "need attention".
- **Search in describe, YAML and JSON.** `/` searches the text of any document view (describe, YAML, JSON, metrics, Helm documents, Copilot answers), ignoring case. `n` and `N` jump between matches and wrap around, every match on screen is highlighted, and Esc clears the search before it closes the view. In the table `/` is still the row filter.
- **`?` shows the keys of the view in front.** For a resource table it lists the actions that apply to that kind (Pods: logs, shell, port-forward; Nodes: cordon, drain, node shell; Deployments: scale, restart), grouped by purpose, and marks an action this session cannot run with the reason. Document views list their search keys. Tab still shows every key. The old flag reminders such as `(--allow-exec)` are gone from key descriptions.
- **k9s columns and predefined column names.** Nodes show NAME, STATUS, ROLE, ARCH, TAINTS, VERSION, CPU, %CPU, CPU/A, MEM, %MEM, MEM/A and AGE, with OS-IMAGE, KERNEL, INTERNAL-IP, EXTERNAL-IP and LABELS in wide mode. Deployments, StatefulSets, DaemonSets, Services, Jobs, CronJobs, PersistentVolumeClaims and Ingresses get their k9s columns too. About 40 predefined columns (`%CPU/R`, `%MEM/L`, `QOS`, `SA`, `ROLE`, `VERSION`, `TYPE`, `PORTS`, ...) can be used by name in `views.yaml`; `kborg views init` writes the built-in columns as a file to edit and `:columns` lists what is shown and what is available. When a table is too narrow, columns drop from the right and AGE goes last.
- **Copilot for people who already use it.** `kborg copilot setup` now works with the standard npm install of the Copilot CLI: it finds the native binary inside the package instead of refusing the Node loader. Ctrl-G asks about the screen in front from any view (the header shows the hint once Copilot is connected), `:copilot status` lists the keys and commands, and `explain` can be bound in `keymap.yaml`. A real question and a follow-up were run end to end on 2026-11-12 with synthetic demo data.
- **Faster keys on large tables.** The summary line no longer classifies every row on each frame: key-to-frame latency at 20,000 rows fell from about 37 ms to under 9 ms and no longer grows with the row count. The header's usage line reads the Node list once every five minutes and node metrics every 15 seconds.
- **Dependencies**: kube 5.0 and k8s-openapi 0.29 (Kubernetes 1.37 types); the minimum supported API stays 1.34.

Pre-release **0.5.0-rc.5** (2026-10-27) adds:

- **Clearer header and footer, in your theme's colors.** The context line labels CTX, NS and API in a muted tone, with the namespace in the accent color. The freshness state (LIVE, STALE, SAMPLE) is a filled chip, and counts and sort sit further apart; READ ONLY and DEMO are chips too. The table title keeps the kind and position in the accent color and the metrics note muted. The status line has a colored edge (accent for news, warning for problems), and key hints are keycaps.
- **Marked rows are highlighted.** Space-marked rows get a tinted background from the theme's warning hue, separate from the cursor row, so a multi-row selection is visible at a glance; the summary shows how many rows are marked. Each theme gets the strongest tint that keeps text and status colors at 4.5:1.
- **Smaller list views**: ConfigMaps, ServiceAccounts, RBAC objects, Endpoints, Leases and other kinds whose columns need only metadata are listed and watched as `PartialObjectMetadata`, so data, spec and status no longer cross the wire or sit in memory. Describe, YAML, export and every write still fetch the full object by name and UID. A `views.yaml` column that reads beyond name, namespace, labels, UID, resourceVersion or timestamps switches that resource back to full objects. Rows are shared with the watch cache instead of copied, and large lists show their first page while the rest loads (`LOADING`). 5,000 ConfigMaps: 33 MiB instead of 67, first page in 0.05 s.
- **Performance gate**: the CI bench job measures demo-scale 5k/20k Pod load, filter and sort, key-to-frame latency (p50/p95/p99), binary size, RSS and idle CPU, compares them with a committed per-OS/arch baseline, fails on a regression over 15 % and posts the delta table to the job summary. `--update-baseline` records intentional changes ([PERFORMANCE.md](PERFORMANCE.md#performance-gate-ci)).
- **Per-context settings** like k9s: `contexts/NAME.yaml` sets the namespace, the view shown on entry, the theme, a header badge (for example a red PROD) and `read_only`/`strict_confirmations` for one context. `:ctx-config` edits it in `$EDITOR`; restrictions only ever tighten, and an invalid or untrusted file makes its context read-only until fixed. See the [reference](themes.md#per-context-settings).
- **Audit sink for SIEMs**: an operator config can write every change to a hash-chained, owner-only JSON-lines file (`audit_file`, rotated) and/or local syslog (`audit_syslog`), one intent record on approval and one outcome record, with identities and the approved review's SHA-256 but never values. `audit_required` blocks a change that cannot be audited. `kborg audit verify` detects removed, inserted or edited lines. See [Operations](OPERATIONS.md#audit-sink-for-a-siem).
- **Copilot follow-ups**: `f` on an `:ask` answer asks another question about the same screen, carrying the conversation, with a fresh review and approval. `:ask` in a filtered logs view also sends the selected lines, and `:explain` asks about the error on the status line. See [Copilot](COPILOT_INTEGRATION.md#ask-about-the-screen-ask).
